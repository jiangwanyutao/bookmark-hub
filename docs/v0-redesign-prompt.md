## 完整提示词（复制下面全部内容）

请为一个名为 **Bookmark Hub** 的浏览器书签管理扩展重新设计整套界面。它是 Chrome/Edge MV3 扩展，主界面是一个在浏览器标签页里全屏打开的 Dashboard 页面。目标用户是书签很多（几百到上万条）的开发者和知识工作者，核心价值是：**检测失效链接、清理重复、用 AI 智能体把书签重新整理成清晰的分类体系，所有改动都可撤销。**

### 技术约束（必须遵守）

- React 19 + TypeScript，**纯客户端组件**：不要用 Next.js 的路由、`next/image`、`next/link`、Server Components、Server Actions、`"use server"`。页面之间用 `useState` 切换视图，不是 URL 路由。
- UI 用 **shadcn/ui（new-york 风格）+ Tailwind CSS v4 + lucide-react 图标**，颜色全部走 shadcn 的 CSS 变量（`bg-background`、`text-muted-foreground`、`bg-primary` 等），不要写死十六进制颜色。
- 对话相关组件用 **AI Elements**（Conversation、Message、Reasoning、ChainOfThought、Shimmer）。
- 主色保持品牌紫：`--primary: oklch(0.541 0.247 293.009)`，暗色模式 `oklch(0.702 0.183 293.541)`。暗色**跟随系统**（`prefers-color-scheme`），不需要切换按钮。
- 所有界面文案**使用简体中文**。数据用写死的 mock 数据演示，不要调用 `chrome.*` API。
- 桌面优先，最小宽度 1024px，在 1280–1920px 下都要好看；列表可能有上万条，长列表要按虚拟滚动的布局来设计（固定行高）。
- 无障碍：图标按钮要有 `aria-label`，状态不能只靠颜色区分，尊重 `prefers-reduced-motion`。
- 品牌 logo 是一个灯塔图标（用占位图 `/icon-48.png` 即可）。

### 设计方向

- 气质：**冷静、专业、信息密度适中的工具型产品**，参考 Linear、Raycast、Arc 的设置页。不要营销页风格、不要大面积渐变和插画。
- 建立清晰的层级：页面标题 + 一句说明 → 关键数字 → 需要处理的事项 → 明细。
- 危险操作（删除）用 destructive 色并二次确认；AI 相关功能用紫色点缀和 ✨ 类图标区分。
- 统一的空状态、加载状态（骨架屏）、错误提示样式；错误提示要写清原因和解决办法。
- 批量操作完成后用 toast 提示，toast 上带「撤销」按钮。

### 整体框架

- **顶栏**（高 56px）：左侧 logo + 「Bookmark Hub」；中间全局搜索框（占位符「搜索标题、网址、目录…」，输入后跳到「全部书签」并过滤）。可以加 ⌘K 快捷键提示。
- **左侧导航**（宽约 200–220px，可折叠成图标栏），分组：
  - 概览：总览
  - 书签：书签导航、全部书签、智能整理
  - 清理：健康扫描、失效链接、重复书签、重定向、待确认（这几项旁边显示待处理数量徽标）
  - 系统：操作记录、设置
- **主内容区**：独立滚动。

### 各页面内容

1. **总览**
   - 「书签健康度」大分数（0–100，环形或仪表盘），旁边一句解读。
   - 数字卡片：总书签、文件夹、失效链接、重复书签、永久重定向、还没扫描的书签数。
   - 「需要你处理」清单：每行一个问题（如「12 个失效链接」「8 条重复书签」「30 个书签还没扫描」），右侧是「立即处理 / 清理重复 / 扫描书签 / 批量更新」按钮；没有问题时显示「没有需要处理的问题。」
   - 「书签地图」：Treemap，面积代表各目录的书签数，点击进入对应目录。
   - 「收藏最多的网站」：域名 + favicon + 数量的排行。

2. **书签导航**（类似 iTab 的起始页）
   - 左侧只列一级分类；右侧顶部是二级目录标签页「全部 / 子目录A / 子目录B…」。
   - 主体是网站图标磁贴网格（favicon + 标题），悬停显示网址。
   - 顶部搜索「搜索书签，回车搜网页」，没有匹配时提示按回车去网上搜索。

3. **全部书签**（三栏）
   - 左：文件夹树（可展开，显示每个目录的书签数，顶部「全部书签」）。
   - 中：书签列表（favicon、标题、域名、所在目录、标签、健康状态小圆点），支持多选和批量移动/删除。
   - 右：详情面板（标题、网址、网站、目录、添加时间、标签编辑、编辑/移动/删除按钮）。

4. **智能整理**（AI 智能体，重点页面）
   - 未开始时：**范围选择卡片**——可勾选的目录树（勾选父目录时子目录自动勾选并禁用，右侧显示书签数）+「新分类体系建在 [下拉选择目录]」+「开始整理」主按钮，上方一句说明「智能体会提出分类体系，过程中你可以随时插话调整，确认后才会移动书签」。
   - 开始后左右两栏：
     - 左栏**对话**：顶部状态条（「智能体工作中… / 等你回答 / 已完成，去右侧预览并确认」+ 已用 tokens）；消息区自动贴底；用户消息右侧气泡；智能体回复为 Markdown；可折叠的「思考过程」；连续的工具调用合成**步骤链**（查看书签、提出分类体系、分配 20 个书签到「教程」…，执行中的步骤带动画）；智能体提问时底部出现问题卡片和选项按钮；底部输入框「插话调整，例如：中台并到后端」+ 发送 + 停止。
     - 右栏**整理方案**：整理范围、新体系建在哪、分类树（最多 3 层，一级不超过 6 个，每个分类右侧书签数）、未归类数量、「预览并确认整理」按钮（完成时高亮）、「重新开始」。
   - **确认整理弹窗**：四个统计（新建目录 / 移动书签 / 删除空目录 / 跳过）、按分类折叠的书签清单（长标题截断，不许撑破弹窗）、说明「移空的旧目录会一并删除，执行前自动创建恢复点，可以在操作记录里撤销」、取消 / 确认整理。
   - 页面下方「AI 标签」卡片：说明「给书签打上主题标签，搜索时能按标签找到」、还有多少书签没标签、生成标签按钮和进度条。
   - 未配置 AI 时显示引导卡片和「去设置」按钮。

5. **健康扫描**
   - 扫描进度（进度条 + 已扫描/总数 + 当前速度），开始 / 暂停 / 继续扫描按钮。
   - 状态分布：正常、失效、重定向、待确认、已跳过、未扫描（带数量和颜色语义，同时有图标）。
   - 网络状态提示（「网络正常」/ 网络不可用）。

6. **失效链接 / 重定向 / 待确认**（同一套列表模板）
   - 顶部：标题、数量、「按原因筛选」（如 404、DNS 失败、超时、证书错误）、全选。
   - 列表行：勾选框、标题、网址（重定向页显示「旧网址 → 新网址」）、原因徽标、所在目录、打开 / 重新检测 / 忽略。
   - 批量操作栏（选中后出现在底部）：失效页「删除 N 个书签」、重定向页「更新重定向网址」、待确认页「忽略 / 重新检测」。
   - 空状态：「没有失效链接。」等。

7. **重复书签**
   - 分组卡片，每组标注类型：完全重复 / 规范化后重复 / 疑似重复，以及「跨目录」标记。
   - 组内每条显示标题、网址、目录、添加时间，用单选选择保留哪一条；按钮「保留选中，删除其余 N 条」。
   - 顶部「一键清理重复书签」。

8. **操作记录**
   - 批次时间线：每个批次显示名称（如「AI 智能整理」「清理重复」）、时间、操作摘要（新建 / 移动 / 编辑 / 删除 各几项）、「已创建恢复点」标记、「撤销」按钮；已撤销的批次置灰并标「已撤销」。
   - 「恢复点」区：说明「批量操作前自动创建，保留最近 20 份及 30 天内的全部」；每个恢复点可「对比并恢复」，弹窗展示差异（被删的、被挪走的、改过标题或网址的、之后新增的不会删除），确认后恢复。

9. **设置**
   - 「AI 服务」卡片：Base URL（提示「填到 /v1 这一级」）、API Key（已保存时显示「已保存，留空则不修改」）、模型名、「发给 AI 的信息」隐私等级单选（仅标题 / 标题 + 域名（推荐）/ 完整网址，并注明「内网地址的书签一律不发送」）、「保存并测试连接」按钮与结果提示。
   - 「需要 VPN 的网站」：域名列表的增删（输入框占位「请输入网站域名，例如 wiki.company.com」），这些网站扫描时不判为失效。

### 交付要求

- 先输出：设计 token（颜色、圆角、间距、字号）、整体框架（顶栏 + 侧栏 + 主内容区）和**总览**页面。
- 组件拆分合理，每个页面一个组件（如 `Overview`、`LauncherView`、`BookmarksView`、`AgentOrganizeView`、`ScanView`、`IssuesView`、`DuplicatesView`、`HistoryView`、`SettingsView`），方便我替换进现有项目。
- 同时展示亮色和暗色效果。
